## ⚠️ Discovered Issue: `import std` Not Production-Ready

### The Problem

`import std;` syntax, while elegant, is **not yet stable** in any major compiler as of Jan 2026:

**GCC 14+**: Requires manual compilation of std module, complex setup
**Clang 20**: Has std.cppm but with compilation errors (missing definitions, module conflicts)
**MSVC 19.36+**: Windows-only, limited platform support

### Attempted Solutions

1. **✗ Build std module from Clang's std.cppm**
   - Result: 20+ compilation errors
   - Issue: Module redefinition conflicts with modulemap
   - Conclusion: libc++ std module implementation incomplete

2. **✓ Fall back to traditional `#include` in module preamble**
   - Pattern:
     ```cpp
     module;
     #include <iostream>
     #include <vector>
     // ... other headers

     export module envpool.env.classic_control.cartpole;
     // module content
     ```
   - Status: **Implemented but hit template export issues**

### Remaining Build Issues

When building with traditional includes, encountered:
```
error: exported templates are unsupported
error: extraneous template parameter list in alias template declaration
```

These are Clang 20 C++20 modules implementation limitations.

## 🔬 Technical Insights

### Why `import std` Fails

1. **Compiler Immaturity**: C++20 modules are cutting-edge (2020 standard)
2. **Standard Library Gap**: Most std libraries not modularized yet
3. **Build Complexity**: Requires pre-compiled module units
4. **Tooling Lag**: Build systems (CMake, Ninja) still adapting

### Module Format Benefits (Still Valuable!)

Even without `import std`, C++20 modules provide:
- ✅ **Faster compilation** (pre-compiled interfaces)
- ✅ **Better encapsulation** (explicit exports)
- ✅ **Cleaner dependencies** (no header include order issues)
- ✅ **Future-proof** (when tooling matures)

### Recommended Path Forward

**Option A: Wait for GCC 14 / Clang 21** (3-6 months)
- More mature `import std` support
- Better template export handling
- Proven in production

**Option B: Hybrid Approach** (2-3 hours work)
- Keep modules for structure
- Use traditional headers for std library
- Fix template export syntax issues
- Achieves 80% of benefits now

**Option C: Traditional Build** (immediate)
- Use existing header-based builds
- Revisit modules in 2027
- Focus on functionality first
